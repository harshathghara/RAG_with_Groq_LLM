# Upcoming Enhancements

A tracked list of planned features and improvements for the RAG PDF Chat project.

---

## RAG Quality

- [ ] **Conversation memory** — Pass the last N exchanges to Groq so it can answer follow-up questions like "tell me more about that" or "what did you mean by X".
- [ ] **Smarter chunking** — Upgrade from fixed character count to semantic chunking (split on paragraph/section boundaries) or sentence-window chunking for better context preservation.
- [ ] **Parent-document retrieval** — Store small chunks for search but pass larger surrounding paragraphs to the LLM. Gets more relevant context without hurting retrieval precision.
- [x] **Hybrid search (BM25 + vector)** — Combine keyword search (BM25) with semantic search and merge results via Reciprocal Rank Fusion. Catches exact-match queries that semantic search misses.
- [ ] **Query rewriting** — Before searching, send the user's question to Groq to rewrite it into a cleaner retrieval query. Improves results for vague or conversational questions.
- [x] **Source citations** — Return the page number and chunk position alongside each answer so the user knows exactly where the information came from. CrossEncoder confidence score (sigmoid %) also shown on each chunk card.

---

## Multi-document Features

- [ ] **Cross-document querying** — Let the user ask a question across all uploaded PDFs simultaneously and synthesize a combined answer. Useful for comparing documents.
- [ ] **Document tagging / collections** — Organize documents into named groups (e.g. "Work", "Research") and search within a group.

---

## UI / UX

- [ ] **Persistent chat history per document** — Store each document's conversation in `localStorage` so switching back to a PDF restores the previous chat.
- [ ] **PDF viewer panel** — Show the actual PDF alongside the chat. Highlight the retrieved chunks directly in the PDF using `pdf.js`.
- [x] **Suggested follow-up questions** — After each answer, show 2–3 suggested follow-up questions (generated by Groq) as clickable chips.
- [x] **Markdown rendering** — AI answers render formatted markdown (bold, lists, code blocks) instead of plain text.
- [x] **Chat download as PDF** — Download the full conversation as a clean, light-themed PDF file with one click.
- [x] **Copy answer button** — One-click copy button on each AI response.
- [x] **Like / dislike buttons** — Thumbs up / down feedback buttons on each AI response, always visible after the answer completes.
- [x] **Dark / light mode toggle** — Toggle between dark and light themes, preference saved in localStorage.

---

## Backend / Infrastructure

- [ ] **User authentication** — Add login so each user only sees their own documents. Use JWT or session cookies.
- [ ] **Persistent storage** — Replace the in-memory `docs` dict with a database (SQLite for simple, PostgreSQL for production) so documents survive server restarts.
- [ ] **File validation & OCR** — Enforce max file size, detect password-protected PDFs, handle scanned PDFs with OCR using `pytesseract`.
- [ ] **Rate limiting** — Prevent abuse on the `/query` endpoint using `slowapi` (FastAPI rate limiting library).
- [ ] **Background job queue** — Replace raw threading with Celery + Redis for robust background processing — retries, progress tracking, worker scaling.

---

## Developer / Ops

- [ ] **Docker support** — `Dockerfile` + `docker-compose.yml` so the whole stack runs with one command anywhere.
- [ ] **Usage analytics** — Log queries, response times, and hit rates to understand how the system is actually being used.
- [ ] **REST API documentation** — Document all FastAPI endpoints with descriptions and examples (auto-served at `/docs`).
